# 需求规范模板

需求规范填写模板。条款写「系统必须做到什么、怎么算通过」。集合名、字段名、函数名、接口路径不进需求条目，放到现状快照或方案文档。

判断口诀：把这条交给不看代码的测试同学，能否判通过或不通过。不能，就是写细了。

| 模板 | 路径 | 适用 |
|------|------|------|
| 成体系 | [成体系/](./成体系/README.md) | 多条需求、多人维护、要对外定版 |
| 单文件 | [单文件/需求规范.md](./单文件/需求规范.md) | 范围小、一个人写完就能评审 |

两套用同一套编号和同一条红线。项目变大时，按单文件文末的拆分对照迁到成体系，编号保持不变。

## 编号

| 前缀 | 含义 | 例子 |
|------|------|------|
| R | 一条用户能单独提出的需求 | R4、R4.1 |
| U | 用语、优先级、分期叫法 | U1 |
| E | 角色、权益、额度等身份口径 | E2 |
| M | 业务对象的状态与数据口径 | M2 |
| B | 本期不做、预留不得封闭 | B1 |

编号只增不复用。作废的保留编号，状态改为「作废」。交叉引用写编号并链到文件，不写「第 3 章」「§1.8」。

## 两条工作流

1. **加需求**：只改活文档（成体系的 `需求分析/`，或单文件里对应小节）。新需求的对外规格一律写「未纳入」。
2. **定版**：另存一份带版本号和日期的规格说明书。上一版不改。定版删掉现状快照、实施分期和实现细节，只留承诺、验收、范围外和已知问题口径。

## 写法对照

| 不要写成 | 写成 |
|----------|------|
| 某字段取 60，越界抛错 | 两项时差须小于 60 秒；超限须标为时差超限并进入告警 |
| 页面调用某个接口 | 登录后须能看到健康分布和未关闭告警数 |
| 某角色函数返回一组模块码 | 值班员须能进入值班与告警，不得进入用户管理 |
