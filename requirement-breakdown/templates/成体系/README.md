# 【系统名称】需求文档

活文档在 [需求分析/总览.md](./需求分析/总览.md)：按需求编号维护条款、验收和实现对照。叙事摘要、范围和完成度见 [需求概览](./需求分析/需求概览.md)，概览不替代条款。

建设分期称一期、二期、三期。实施计划里的冲刺分段另起名字（例如段一、段二），二者不要混用。见 [U3](./需求分析/通用规格/用语与优先级.md)。

| 路径 | 说明 |
|------|------|
| [需求分析/总览.md](./需求分析/总览.md) | 总览、核心流程、需求台账 |
| [需求分析/需求概览.md](./需求分析/需求概览.md) | 建设意图、范围边界、工期和完成度 |
| [需求分析/需求/](./需求分析/需求/_模板-需求条目.md) | 单条需求的条款与验收 |
| [需求分析/通用规格/](./需求分析/通用规格/README.md) | 跨需求共用的口径 |
| [需求分析/backlog.md](./需求分析/backlog.md) | 尚未落地的事项，挂到 R 编号 |
| [需求规格说明书/](./需求规格说明书/README.md) | 对外定版。未定版前可以空着 |

实施计划、排期和方案不是需求基线。方案文档头部写「关联需求」，需求 frontmatter 的「方案文档」指回去。

## 修改纪律

1. **加需求只动 `需求分析/`。** 新需求的「对外规格」写「未纳入」。
2. **需求编号只增不复用。** 作废的需求保留编号并标状态。
3. **交叉引用用需求编号，不用章节号。** 写 R4.5、E3、M2，并链到具体文件。
4. **跨需求的约束写进 `通用规格/`。** 不要在单个需求里各写一遍。
5. **改了需求 frontmatter，就同步总览台账。** 台账位于 `<!-- 台账:开始 -->` 与 `<!-- 台账:结束 -->` 之间。

## 加一条需求时要动的文件

| 文件 | 怎么改 | 何时可跳过 |
|------|--------|------------|
| `需求分析/需求/RNN-简短标题.md` | 从 [_模板-需求条目.md](./需求分析/需求/_模板-需求条目.md) 复制，删掉注释 | 不可跳过 |
| `需求分析/总览.md` 台账 | 增加一行，与 frontmatter 一致 | 不可跳过 |
| `需求分析/修订记录.md` | 倒序置顶一行，「需求」栏写 R 编号 | 不可跳过 |
| `需求分析/backlog.md` | 未完成的挂到 R 编号；全部落地的挪到已完成 | 需求已全部落地 |
| `需求分析/通用规格/` | 改共享约束 | 不碰共享约束 |
| `需求分析/术语表.md` | 登记新产品名，并写禁用叫法 | 没有新名词 |
| `需求分析/案例库.md` | 记下现象、原因、对应条款 | 不是问题驱动 |
| 方案文档 | 头部写关联需求 | 没有方案，frontmatter 填 `—` |
| 总览「相关文档索引」 | 补新方案一行 | 没有新方案 |

落点：用户能说出一件台账里没有的事，就新建 `RNN`（最大编号 +1）。同一目标下的细化，在该文件加 `RNN.k`。拿不准就挂子编号。
