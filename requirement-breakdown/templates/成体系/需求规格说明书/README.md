# 需求规格说明书

对外定版目录。上一版提交后不改；变更新建下一版。

文件名：`需求规格说明书-{用户侧|运营侧}-V1.x-YYYY-MM-DD.md`。

| 版本 | 日期 | 文件 | 说明 |
|------|------|------|------|
| — | — | — | 尚未定版 |

## 版本规则

| 变化 | 版本号 |
|------|--------|
| 增补需求、订正口径、范围小幅扩张 | 小版本 +1（V1.0 → V1.1） |
| 承诺范围重构、受众调整、大批需求收编 | 大版本 +1（V1.x → V2.0） |

## 定版时做的事

1. 和读者确认收编哪些需求。默认只收「已落地」和「部分落地」里已经落地的条款。待办不收。
2. 把收编需求的对外规格改为 `待纳入 V1.x`，并同步总览台账。
3. 复制上一版骨架，新需求插进对应功能节。没有上一版时，用本目录两份骨架。
4. 删掉现状快照、实施分期、内部排期，以及集合名、字段名、函数名。
5. 写完后把对外规格改为 `V1.x（用户侧）`、`V1.x（运营侧）` 或 `V1.x（用户侧 + 运营侧）`。
6. 在需求分析修订记录置顶一行。本表置顶一行。

## 受众

| 侧 | 谁照它验收 |
|----|------------|
| 用户侧 | 业务用户能自己感知、自己验收 |
| 运营侧 | 只有运维或账号管理员接触 |
| 两侧都写 | 同一能力两类读者关心的面不同，须按受众重写，不复制同一段 |
| 都不写 | 纯工程内部改动：目录、脚本、缓存、字段重命名 |

两侧都要有的四块：范围表、范围外、已知问题口径、需求优先级。缺了会被当成没有边界。

## 不在本版范围内的需求

定版后把未收编的 R 编号列在这里，避免和规格正文混读。
