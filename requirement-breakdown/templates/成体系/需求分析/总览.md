# 【系统名称】— 需求分析

> 状态：生效中（YYYY-MM-DD 建立）。后续变更见 [修订记录](./修订记录.md)。
> 性质：**活文档**。研发全量基线，随迭代增补。叙事摘要见 [需求概览](./需求概览.md)。
> 范围：【本期交付一句话。写清主线，以及明确不作为对外稳定服务的能力。】

本页是**总览与台账**，需求正文按编号分文件存放。加需求只动本目录。对外定版见 [需求规格说明书](../需求规格说明书/README.md)；已定版文件不在加需求时原地修改。

交叉引用用需求编号（如 R4.5、E3、M2），不用章节号。编号只增不复用。

## 1. 核心流程

```
【步骤 1】 → 【步骤 2】 → 【步骤 3】 → 【步骤 4】
```

| 阶段 | 用户行为示例 | 系统行为 |
|------|-------------|----------|
| 【阶段名】 | 【用户做什么】 | 【系统必须怎样，并链到 R 或通用规格编号】 |

## 3. 非功能需求

| 项 | 要求 |
|----|------|
| 用语 | 「应 / 宜 / 可」和 P0–P2 见 [U1](./通用规格/用语与优先级.md)、[U2](./通用规格/用语与优先级.md) |
| 分期 | 建设分期与实施分段的叫法见 [U3](./通用规格/用语与优先级.md) |
| 范围 | 本期不做与必须预留的能力见 [B1](./通用规格/范围边界.md) |
| 性能 | 【并发、数据规模、响应时限、试运行天数；细则放在对应 R】 |
| 安全 | 【等保或等价要求、审计留存、认证；细则放在对应 R】 |
