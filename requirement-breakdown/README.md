# requirement-breakdown

给它一段话，它把这段话拆成一条条需求，对照已有需求决定是更新还是新建，再按需求规范模板写成需求规范。

原文可以是功能描述、需求描述、分析研究、测评结果、界面设计、问题反馈、会议纪要，或者几样混在一起。

> **说明**：本文件供**人类**查阅。Agent 读的是 `SKILL.md`。

---

## 怎么调用

点名 `/requirement-breakdown`，或者直接说「把这段话拆成需求」「写成需求规范」。原文贴在后面，或者给一个文件路径。

```
/requirement-breakdown 客服反映工单太多看不过来，希望工单列表能按处理人筛选，并且同一客户同一问题 10 分钟内重复提交的合并成一条。
```

```
/requirement-breakdown 把 docs/research/xxx测评报告.md 里的结论落到需求里
```

指定存放路径和模板：

```
/requirement-breakdown 存到 docs/requirements/频谱监测平台，用单文件模板：……（原文）
```

不指定时，存放路径是 `docs/requirements`，模板是成体系。

## 它会先给你一张清单

动文件之前，它会列出每句原文拆成了什么、判成哪一类、打算写到哪：

| 判定 | 意思 |
|------|------|
| 已包含 | 现有条款已经写了，不改 |
| 细化 | 同一件事写得更具体了，改现有条款或加子编号 |
| 交叉 | 牵涉几条需求，放进主责的那条，其余的写清分工 |
| 冲突 | 和现有条款矛盾，**等你定** |
| 新门类 | 现有需求里没有，新建编号 |
| 不入需求 | 实现细节或个人倾向，不写进条款 |

你确认或改完再写。想跳过确认就说「直接写」，但有冲突、或要新建一整套体系时仍会停下来问。

原文没给的数字（时限、条数、阈值）不会被编进去，会列成「待确认」。

## 写到哪

| 情况 | 结果 |
|------|------|
| 存放路径已有需求体系 | 在那套体系里增改，沿用它的文件名和编号；同步修订记录、backlog、术语表、案例库，重建台账 |
| 存放路径没有需求体系 | 复制模板新建。成体系得到 `README.md`、`需求分析/`、`需求规格说明书/`；单文件得到 `<系统名称>-需求规范.md` |

模板优先用项目里的 `docs/requirements/需求规范模板/`，没有就用本技能自带的 [templates/](templates/README.md)。

它不会动任何 `需求规格说明书/` 下的文件。新条款一律是「未纳入」对外规格。

## 挂到项目里

和本库其他技能一样，用 Junction 挂到项目的 `.cursor/skills/requirement-breakdown`，并在项目 `.gitignore` 里忽略这个目录。见本库根目录 [README](../README.md)。

## 项目专属说明

项目的需求目录和模板不一样、有自己的校验脚本或定版流程时，在项目里写一份：

```
<项目根>/.cursor/skills/requirement-breakdown.project.md
```

它放在 Junction 旁边，不在 Junction 里面，所以随项目提交，不会写进本库。Agent 开工前会先读它，其中的约定优先于技能默认做法。建议写这几块，没有的就不写：

| 小节 | 写什么 |
|------|--------|
| 已有体系 | 默认路径下的需求目录叫什么，和模板的文件怎么对应（总览文件名、条目模板位置、没有的文件） |
| 通用规格对照 | 模板的 U / E / M / B 在本项目对应哪个文件，哪些编号前缀已被占用 |
| 校验 | 项目自己的校验命令，以及仓库里已有的无关 FAIL |
| 定版 | 出需求规格说明书用哪个技能或流程 |
| 相邻技能 | 哪些事归别的技能管 |

## 自己跑脚本

```powershell
# 看某个路径下已有哪些需求体系、下一个编号、各需求状态
python .cursor/skills/requirement-breakdown/scripts/req_tool.py scan docs/requirements

# 自检任意路径下的成体系或单文件，并按 frontmatter 重建台账
python .cursor/skills/requirement-breakdown/scripts/req_tool.py check docs/requirements/频谱监测平台 --fix-index
```

只用 Python 标准库，项目用 uv 时前面加 `uv run`。
