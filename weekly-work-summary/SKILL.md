# 周工作总结生成

将用户提供的分模块、分点罗列的工作内容，改写为一段连贯的中文工作总结。支持三个可选参数：**字数范围**、**总结格式**、**输出内容格式**。

## 输入特征

用户通常会给出类似结构：

```
1. 模块A：
   1. 子项...
   2. 子项...
2. 模块B：
   ...
```

模块通常是技术领域的功能线（如中控系统、链路、NLU、TTS/ASR），每个模块下有若干条已完成或进行中的具体工作。

## 可配置参数

用户可在请求中显式指定以下三个参数；未指定的按默认值处理。请从用户的自然语言中识别这些意图（如"控制在150字内""用列表""输出Markdown"）。

### 1. 字数范围（word_count）

- **默认**：200 字以内。
- **支持形式**：
  - "x 字以下 / x 字以内 / 不超过 x 字"：上限为 x，无下限。
  - "m-n 字 / m 到 n 字 / m~n 字"：字数落在 [m, n] 区间内。
  - "x 字左右 / 约 x 字"：允许 ±10% 浮动。
- **判定口径**：按中文字符数计（标点、空格、英文单词按实际字符估算，术语如 directive 计为一个整体但按字符长度累加）。
- **超限处理**：
  - 超过上限时，进一步压缩次要细节（具体厂商名、子任务、修饰词），保留最核心的结果性表述。
  - 若信息量过大导致下限区间难以覆盖全部模块，优先保证**每个模块至少一句话**，宁可精简也不遗漏整个模块。
  - 若内容过少不足下限，可适度补充每条工作的结果性描述，但**不得编造**未提供的信息，也不加套话凑字数。

### 2. 总结格式（summary_format）

- **默认**：一段话。
- **支持形式**：
  - **一段话**：不分段、不分点，按模块顺序用分号/句号自然衔接成连贯的一段。
  - **列表清单**：每个模块一个条目（可含 1-2 条要点），条目内保持简洁的动作+结果表述。
  - **分模块小标题**：每个模块用小标题，标题下用短句或要点描述（适合模块多、内容较丰富的场景）。
  - 其他用户明确要求的常用格式（如表格），按用户描述组织。
- 该参数决定**内容的组织结构**，与"输出内容格式"（下方）正交：例如"列表清单 + 普通文本"用 `-`/`1.` 等纯文本符号，"列表清单 + Markdown"用 Markdown 列表语法。

### 3. 输出内容格式（output_format）

- **默认**：普通文本。
- **支持形式**：
  - **普通文本**：纯文本，不使用任何标记语法。列表用 `1.`、`-` 等朴素符号，标题用纯文字。
  - **Markdown**：使用 Markdown 语法（`#` 标题、`-`/`1.` 列表、`**加粗**` 等），适合粘贴到支持 Markdown 的文档。
  - **HTML**：输出 HTML 片段（如 `<p>`、`<ul><li>`、`<h3>` 等），不含 `<html>/<body>` 等外层文档结构，便于直接嵌入。
- 该参数只决定**最终文本用什么标记语法呈现**，不改变内容取舍与字数口径。

## 输出要求（通用，与参数无关）

1. **内容取舍**：
   - 只保留每条工作中最核心的动作和结果（做了什么、达成了什么），去掉过程细节、原因分析、排期展望等非结果性内容。
   - 术语、专有名词（如 directive、VAD、RAG、productId）保持原文不变，不做解释、不展开背景。
   - 已完成的用"完成/落地/修复/新增"等动词；进行中或待办的可用"推进/跟进/确认方案"等区分语气，但不需要特别强调进度状态。
2. **语言风格**：符合公司技术周报的书面语气，简洁、无套话、无总起总结句（不要"本周工作总结如下"之类的开头/结尾废话），直接进入内容。
3. **结构**：按模块顺序组织，用"XX方面/XX模块"或直接以模块名开头衔接。

## 工作流程

1. **解析参数**：从用户请求中识别字数范围、总结格式、输出内容格式；未提及的用默认值（200字以内 / 一段话 / 普通文本）。如三者都有明确冲突或歧义再向用户确认，否则按最合理理解执行。
2. **读取内容**：识别模块划分（通常是最外层编号 1./2./3.）。
3. **提炼要点**：对每个模块，提炼 1-2 个最有信息量的动作+结果，形成短句。
4. **按总结格式组织**：一段话→连贯衔接；列表清单→每模块一条目；分模块小标题→标题+要点。
5. **按输出内容格式渲染**：普通文本 / Markdown / HTML 应用对应的标记语法。
6. **校验字数**：按字数范围检查，超上限则压缩，不足下限则在不编造前提下补充结果性描述。
7. **直接输出**最终结果，不加解释、不加"以下是..."等引导语。

## 示例

**输入（节选）**：
```
1. 中控系统：完成小度意图模拟能力...完成接入协议改造...
2. 链路：自研链路vad配置...炯为AI玩具多轮NLU优化...
```

**输出（默认：200字以内 / 一段话 / 普通文本）**：
```
本周工作聚焦中控、链路、NLU及TTS/ASR四大模块。中控系统完成小度意图模拟能力、接入协议统一改造（directive+payload）...
```

**输出（150字以内 / 列表清单 / Markdown）**：
```
- **中控系统**：完成小度意图模拟能力，落地接入协议统一改造（directive+payload）。
- **链路**：完成自研链路 VAD 配置，优化炯为 AI 玩具多轮 NLU。
```

**输出（一段话 / HTML）**：
```
<p>本周工作聚焦中控、链路等模块。中控系统完成小度意图模拟能力、接入协议统一改造（directive+payload）...</p>
```
