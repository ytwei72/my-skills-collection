# 文档 → 规范美观的 Word（.docx）

> 本 skill 为项目默认可自动发现的 skill 之一。版式对齐「应急包挂硬件方案」一版：藏青 / 青绿 / 橙色、微软雅黑、页眉细线、页脚页码，章节能出现在 Word 导航窗格。

## 何时使用

- 用户要把 **`.md` / `.txt`** 转成 **`.docx` / Word / Word 版 / 导出 Word**。
- 用户强调格式清楚、能在 Word 导航里看到章节。
- 未指定输出路径时：**与源文件同目录、同名改 `.docx`**。不要覆盖用户已经手工改过的同名稿，除非用户要求重做。

## 首选做法：调用附带脚本

```bash
python .cursor/skills/md-to-word/scripts/md_to_docx.py <input.md> [output.docx]
```

仓库里用 `.venv\Scripts\python.exe`。依赖 `python-docx`。脚本幂等，重复运行覆盖指定输出。

脚本覆盖标题、引用、列表、表格、代码块、图片、链接和页眉页脚。公文红头仍走 `official-doc-formatter`（须用户点名）。

## 导航窗格（必须）

Word 导航**不收录表格单元格里的段落**。一级标题如果只写在色条表格里，导航里就只剩下一级。

- 要出现在导航里的标题，必须是**正文段落**，并套用内置样式「标题 1」「标题 2」「标题 3」。色条和底纹用段落边框、段落底纹，不要用表格拼标题。
- **方案 / 调研稿**（全文只有一个 `#`，章用 `##`）：`#` 只作封面标题，**不进大纲**；`##` → 标题 1（导航一级）；`###` → 标题 2（导航二级）；`####` → 标题 3。
- **普通稿**（多个 `#`，或没有这种「单标题 + 多章」结构）：`#` → 标题 1，`##` → 标题 2，`###` → 标题 3。
- 「目录」二字只是版式标签，不要套标题样式，否则它会占掉一条导航。
- 生成后检查：一级、二级标题的 `pStyle` 分别是 `Heading1`、`Heading2`，且**不在** `w:tbl` 内。

## 版式

| 元素 | 约定 |
|------|------|
| 字体 | 全文微软雅黑；代码 Consolas（东亚字体仍用微软雅黑） |
| 颜色 | 藏青 `#1B3A4B`、青绿 `#2A6F7F`、橙 `#C45C26`；正文 `#2C3338` |
| 页面 | A4；左右 1.8 cm、上 2.0 cm、下 1.7 cm，给宽表留出正文宽度 |
| 页眉 | 标题靠左，底边青绿细线；有封面时首页页眉留空 |
| 页脚 | 居中「— 页码 —」 |
| 一级章 | 浅底 + 左侧橙色条，13.5 pt 加粗藏青 |
| 二级节 | 青绿加粗，底边细线 |
| 封面 | 单个 `#` 的方案稿：藏青条 + 橙色条 + 居中标题；开头 `>` 收成标签表 |
| 文内目录 | 章不少于 3 个时，用书签链到各章；目录格不是标题样式 |

## 表格与正文

- 列宽按内容自适应（中文 / 全角计 2），设上限后按比例分到页面宽度；`tblLayout=fixed`，关闭 autofit。5 列及以上用 8.5 pt，4 列用 9.5 pt。
- 表头藏青底白字，跨页重复；隔行浅蓝；首列是短标签时青绿加粗。判定、结论、合计等行用浅沙色底。
- 单元格正文左对齐。支持 `<br>`、单元格内 `![]()` 与 `<img>`。
- `**加粗**` 用藏青突出。`[文字](url)` 与裸 URL 做成可点击超链接（青绿）。
- 引用 `>`：左侧青绿条 + 浅底，不用楷体。
- 有序列表做成序号列 + 正文列。无序列表用青绿圆点、悬挂缩进。
- 以「来源」开头的段落用 9.5 pt 弱化色。
- 围栏代码保持等宽浅底。若代码块是连接关系图（箭头、框线），改成「标签 | 内容」分层表，不要依赖等宽对齐。

## 工作流程

1. 确认源文件与输出路径。
2. 运行脚本。
3. 核对导航：一级、二级都在正文标题样式上，且不在表格里。
4. 核对表格不溢页、图片已嵌入、链接可点。
5. 交付输出路径。
